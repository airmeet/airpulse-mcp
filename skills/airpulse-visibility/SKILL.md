---
name: airpulse-visibility
description: Investigate AirPulse visibility, competitor mentions, citations and the underlying AI answers with one explicit window and cohort, honest coverage states and drill-down evidence.
---

Resolve the brand with `list_brands` unless it is already unambiguous in this session.

**Use the server's answer.** The visibility, competitor and citation reads return a finished answer: markdown text with a bold headline, a scope line, a table, a legend, coverage and caveats. The structured content carries `answer` (`headline`, `scope`, `table`, `legend`, `caveats`, `coverage`, `charts`, `next`) and the full result in `data`. Lead with the headline, which is the dashboard-parity number. Keep the scope and caveat lines with the numbers they qualify, and reuse the table as given. Never recompute, re-round or re-aggregate the numbers. The visibility table is by engine when engine data exists, and otherwise shows the most recent days. `answer.table.truncated` (`{shown, total}`) marks a trimmed table. For other days read `data.series` rather than deriving values. Offer the `next` questions as follow-ups: their `args` are ready to call, and those marked `uses_quota` need the audit-runs rules. Internal IDs (job, prompt, execution, citation IDs and cursors) go in tool calls, never in prose. Leave `format` at its default when answering a person.

**Window and cohort.** Choose one window and pass it to every comparable tool: either `date_range` (`1d`, `7d`, `30d`, `180d`, `365d` — the N complete days before today) or `start_date` + `end_date` (YYYY-MM-DD, inclusive, max 366 days), plus `timezone` (IANA, default UTC) on visibility and competitor tools. Defaults differ (`get_brand_visibility` 7d; `get_competitor_comparison`, `get_citations`, `list_citation_pages` 30d), so always pass the window. Citation tools use UTC days; say so when comparing with a non-UTC visibility series. Optional filters use one vocabulary across these tools: `engines` (chatgpt, claude, copilot, gemini, google_ai, perplexity), `region` (ISO-2 market or `global`), `topics` and `prompt_ids`. The resolved cohort is echoed back; use the same filters everywhere so results describe one cohort, and report `cohort_changed` when the prompt set changed inside the window. `by_engine` is `{engine: {entity_name: score}}`, keyed by the canonical entity name: read the brand's scores under `data.brand_entity`, not the brand's display name, because the two can differ. On `get_brand_visibility` the inner map holds the brand only; on `get_competitor_comparison` it holds every tracked entity. `competitive_analysis` is only returned for unfiltered `date_range` requests. `get_competitor_comparison` does not include cited pages; use the citation tools.

**Scope with every number.** The answer's scope line carries brand, window, timezone and cohort; never infer scope yourself. When quoting a figure from `data`, state the same scope, `latest_observation_at` and the metric reference `{id, version, unit}`. Take unit and formula from `get_metric_definitions` (or the resource `airpulse://metrics/definitions`); never infer them. Keep `result_id` when citing or exporting a result. `compare_previous: true` returns the equal-length window just before with its score and change in percentage points — use it instead of computing your own comparison.

**Coverage.** Each daily bucket has `value` and `coverage_state`: `measured`, `partial` (may be biased), `pending`, `failed`, `not_scheduled` (with a reason), `unknown` or `no_data_in_cohort`. A null value is a gap with a stated state, never zero; only a measured 0 plots at zero. `summary.score` is the mean of days with a value. `get_brand_health` is a digest snapshot dated `as_of`; do not combine its rank or share with live figures as if contemporaneous. If figures disagree and metadata cannot reconcile them, show the disagreement.

**Drill-down** for "why did it change" or "what did ChatGPT say": take the bucket's `job_ids` and call `list_prompt_responses({brand_id, job_id, ...drilldown.with_args})` so answers match the point's cohort, then `get_prompt_response({brand_id, execution_id})` for exact text, `mention_spans`, citations, status (`succeeded` | `empty` | `unknown`) and `degraded`. Job-scoped results list `failed_captures`; report them rather than substituting browsing. For one tracked prompt use `list_brand_prompts` (limit 1–100; follow `pagination.has_more`), then `list_prompt_responses({brand_id, prompt_id, date_range})` and page with `cursor: pagination.next_cursor` on the same prompt. Pass IDs verbatim in tool calls. One answer is an example, not proof of the aggregate. Preserve engine, market, status and timestamp.

**Citations.** `get_citations` returns citation share with a real previous-period change, total versus brand-attributed citations, a daily series (null = no sightings), top domains with `ownership` (`owned` | `competitor` | `third_party`) and the first page of cited pages. Brand-attributed citations are a subset of all-source citations — never describe total growth as brand growth. For a complete list call `list_citation_pages` with window, filters and optional `sort`, `brand_mentioned`, `domain`, `page_size` (1–100); for later pages pass only `brand_id` and `cursor: next_cursor` until `has_more` is false, and state totals from `pagination.total`. Do not call a top list exhaustive. Distinguish a prose mention, an owned citation, a third-party page mentioning the brand, and overall citation activity. Explain competitor citations as hypotheses supported by answers and cited pages; do not claim access to ranking logic.

**Charts.** If the host can draw charts, draw them from `answer.charts`. Each chart gives a type, title, caption, unit and named series, and a null point is a missing run, so it stays a gap. Otherwise show the answer's table. Do not describe a chart you did not draw. Chart and graph requests are reads; never start an analysis to fill gaps.
